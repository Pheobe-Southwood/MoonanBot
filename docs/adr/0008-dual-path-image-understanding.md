# Understand inbound images through native input or a Vision Agent description, never both

Inbound QQ images previously became a `[图片：file]` placeholder and nothing else: the character could not see screenshots, photos, or stickers, and the operator could not fix a provider catalog that under-declares modalities. We now resolve image understanding per consumer at render time. Each Agent slot has an Image Input Capability — the pi-ai catalog's `model.input`, or the operator's per-slot `forceImageInput` override when the catalog is wrong. Image-capable consumers receive the real `ImageContent` inline, newest-first up to `media.maxInjectedImages` (default 10); image-blind consumers receive `[图片：description]` text produced by a new Vision Agent slot, generated lazily on first need and cached permanently, so one image is described at most once no matter how many blind consumers or restarts follow. Because QQ image URLs expire quickly, bytes are downloaded at observation time (segment URL first, `get_image` API fallback, format decided by magic bytes) into a Media Cache whose bytes carry a TTL (default 7 days) while descriptions never expire. Persisted agent state never carries base64: image blocks are replaced by `[图片]` markers when a run ends, and the archive threshold estimates a flat 1500 tokens per image block instead.

## Considered Options

- **Always describe every image (single text path)**: one simple pipeline, but image-capable models lose fidelity (OCR-level text instead of pixels) and every image pays a vision call even when the consumer could have seen it directly.
- **Hand the model the raw image URL**: no storage needed, but provider-side fetches fail against expiring, auth-bound QQ CDN URLs, and the model catalog cannot be relied on to refuse; downloading locally is the only durable option.
- **Describe eagerly at download time**: descriptions exist before anyone asks, but most images are consumed by image-capable models or never rendered at all, wasting vision calls and adding prompt-injection surface for text nobody reads.
- **Dual path keyed by capability (chosen)**: native `ImageContent` for seeing consumers, lazily generated and permanently cached Vision descriptions for blind ones, a configurable injection cap with description fallback for overflow, and strip-on-persist so neither the database of agent state nor backups accumulate base64.
- **External OCR/ffmpeg sidecar for covers and text**: precise for document images, but adds a system dependency and a second extraction path; the Vision model's prompt already requests OCR content, and video covers were cut from scope.
