# Persist custom-provider models as a last-known-good list that an empty refresh never clears

Custom-provider model lists used to live only in process memory: the Web UI always saved `models: []`, and models pulled by a refresh existed solely as pi-ai `dynamicModels` over an empty baseline. Every restart (a version update is a systemd restart), every `rebuild()` triggered by editing any provider, and every upstream hiccup that returned an empty `/models` answer therefore zeroed the selectable list, dangling the Simulation/Synthesis Agent selections and stalling the Character with a consumed wake timer and no recovery path (issue #7). We now treat `custom_providers.models_json` as the provider's **Known Model List**: `ProviderRegistry` fetches custom-provider models itself (outside pi-ai's refresh pipeline, so keyless local endpoints are not locked out by its credential gate), persists every successful non-empty result, re-registers only the affected provider, refreshes all custom providers once in the background at boot, and records `last_refresh_at`/`last_refresh_error` so a kept-behind list is never "inexplicable" in the UI. An empty or failed remote answer always keeps the stored list and surfaces the reason; operator edits preserve both the list and the stored key unless a non-empty replacement list or a new key is explicitly provided.

## Considered Options

- **Keep pi-ai's in-memory store, refresh at boot**: no schema change, but an offline boot or a flaky upstream still yields 0 models and a stalled Character — the durable state that agent selections reference must itself be durable.
- **SQLite-backed pi-ai `ModelsStore`**: persists the dynamic overlay through pi-ai's own restore/publish flow, but adds a parallel cache table with `checkedAt` semantics, still routes refresh through the credential gate (keyless endpoints can never list models), and keeps two sources of truth beside `models_json`.
- **Union or pin-the-selected-model on refresh**: a dropped upstream model could never dangle a slot, but dead models accumulate in the picker and fail only at call time; truthful replacement with an explicit readiness problem ("模型不存在：provider/model") tells the operator exactly what to reselect.
- **Persist last-known-good, replace on non-empty truth, never wipe on empty (chosen)**: one durable list in the existing schema (two nullable columns added), refresh semantics identical for keyed and keyless endpoints, transient upstream glitches demoted to a visible warning, and boot-time recovery without blocking startup.
